# SkaFld VC in Codex

The skills and agent procedures are written for Claude Code. In Codex, read them with these substitutions.

| The text says                                                        | In Codex                                                                                                                                                                                                                                                  |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Load `skafld-vc:<skill>` with the Skill tool                         | Read `skills/<skill>/SKILL.md` in the plugin in full (Codex lists every skill with its file). The person can name one as `$skafld-vc:<skill>`.                                                                                                            |
| Start the `skafld-vc:<agent>` agent (the Agent tool)                 | Codex plugins ship no agents. Where multi-agent is on, call `spawn_agent` with `fork_turns: "none"` and a message that points to `skills/ask/references/<agent>.md` and states the request, then `wait_agent`. Otherwise follow that file yourself, here. |
| `deliverables:<tool>`, `setup:<tool>`, `exa:<tool>`, `apollo:<tool>` | `mcp__deliverables__<tool>`, `mcp__setup__<tool>`, `mcp__exa__<tool>`, `mcp__apollo__<tool>`                                                                                                                                                              |
| `skafld-vc:<tool>` (the platform)                                    | `mcp__skafld_vc__<tool>`, only when the person added their platform to `~/.codex/config.toml` as `[mcp_servers.skafld-vc]` with `url = "<platform address>/api/mcp"` and signed in with `codex mcp login skafld-vc`                                       |
| `${CLAUDE_SKILL_DIR}`                                                | The folder of the skill you are following (the folder of its SKILL.md)                                                                                                                                                                                    |
| Run `node <script>`                                                  | Your shell tool, always as `node <script>`, never `./script`                                                                                                                                                                                              |
| Ask the person                                                       | Ask in your reply and wait for the answer                                                                                                                                                                                                                 |

Always pass `project_dir`, the absolute path of the folder you are working in, to every deliverables and setup tool. In Codex those servers run from the plugin folder, so without it files would be written there instead of in the person's folder.

Only Exa is on when the plugin is installed, because it needs no sign-in. The person turns on another connector in `~/.codex/config.toml`, under the plugin's MCP server settings (for example `[plugins."skafld-vc".mcp_servers.apollo]` with `enabled = true`; `codex plugin list` shows the plugin's id), then signs in with `codex mcp login <server>`.
