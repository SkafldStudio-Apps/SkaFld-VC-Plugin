# SkaFld VC in Codex

The skills and agent procedures are written for Claude Code. In Codex, read them with these substitutions.

| The text says                                                        | In Codex                                                                                                                                                                                                                                                  |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Load `skafld-vc:<skill>` with the Skill tool                         | Read `skills/<skill>/SKILL.md` in the plugin in full (Codex lists every skill with its file). The person can name one as `$skafld-vc:<skill>`.                                                                                                            |
| Start the `skafld-vc:<agent>` agent (the Agent tool)                 | Codex plugins ship no agents. Where multi-agent is on, call `spawn_agent` with `fork_turns: "none"` and a message that points to `skills/ask/references/<agent>.md` and states the request, then `wait_agent`. Otherwise follow that file yourself, here. |
| `deliverables:<tool>`, `setup:<tool>`, `exa:<tool>`, `apollo:<tool>` | `mcp__deliverables__<tool>`, `mcp__setup__<tool>`; `mcp__exa__<tool>` and `mcp__apollo__<tool>` only when the person added that server                                                                                                                    |
| `firecrawl:<tool>`                                                   | `mcp__firecrawl__<tool>`, only when the person added Firecrawl to `~/.codex/config.toml` as `[mcp_servers.firecrawl]` (its address is in the plugin's CONNECTORS.md) and signed in; otherwise there is no Firecrawl fallback                              |
| `skafld-vc:<tool>` (the platform)                                    | `mcp__skafld_vc__<tool>`, only when the person added their platform to `~/.codex/config.toml` as `[mcp_servers.skafld-vc]` with `url = "<platform address>/api/mcp"` and signed in with `codex mcp login skafld-vc`                                       |
| `${CLAUDE_SKILL_DIR}`                                                | The folder of the skill you are following (the folder of its SKILL.md)                                                                                                                                                                                    |
| Run `python3 <script>`                                               | Your shell tool, always as `python3 <script>`, never `./script`                                                                                                                                                                                           |
| Ask the person                                                       | Ask in your reply and wait for the answer                                                                                                                                                                                                                 |

The `deliverables` and `setup` servers come with the plugin and need Node.js 18 or later; without Node, they do not start, so follow the skills' steps for when those servers are not available. Always pass `project_dir`, the absolute path of the folder you are working in, to every deliverables and setup tool and to the Python scorer. In Codex those servers run from the plugin folder, so without it files would be written there instead of in the person's folder.

The plugin declares only the local `deliverables` and `setup` servers. Exa, Apollo, Firecrawl and the other connectors are recommended, not part of the plugin: the person adds each one to `~/.codex/config.toml` as `[mcp_servers.<server>]` with its address (for example `[mcp_servers.exa]` with `url = "https://mcp.exa.ai/mcp"`; the addresses are in the plugin's CONNECTORS.md), then signs in with `codex mcp login <server>` where it needs one. Use a connector only when it is there.
